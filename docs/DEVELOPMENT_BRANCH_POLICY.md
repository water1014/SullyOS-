# 二改分支开发约定

本仓库的糯米机二次开发统一在 `feature/image-studio` 进行。

## 分支职责

- `feature/image-studio`：唯一二改工作分支。所有新增功能、现有功能调整、缺陷修复、测试和二改文档均提交到此分支。
- `master`：上游原版主线。视为用户口中的“main 主线”；只用于跟踪上游更新，不直接提交二改内容，不在此分支开发，不用二改分支覆盖它。
- 当前仓库实际分支列表为 `master` 与 `feature/image-studio`，没有名为 `main` 的分支。除非仓库上游以后改名，否则本约定中的上游主线指 `master`。

## 上游更新流程

当上游 `master` 出现新提交时：

1. 只读比较 `master` 与 `feature/image-studio` 的 ahead/behind、提交和文件差异。
2. 检查上游改动与二改文件的重叠、API 变化、数据库迁移和依赖变化。
3. 在 `feature/image-studio` 内制定整合方案，优先保留二改行为并吸收兼容的上游修复。
4. 有冲突时逐项解决并运行测试、构建；未通过前不宣称整合完成。
5. 不向 `master` 回推二改提交，不自动合并，不强推，不重写历史。

## 发布边界

- 功能预览只从 `feature/image-studio` 构建。
- 正式发布流程必须单独确认；本约定不授权部署到正式站点。
- 任何数据库升级、旧资产迁移、清理或云端资源变更都必须先备份并验收。

## 助手执行约束

每次开始修改前先核对当前分支；每次提交后核对提交落点。若分支不明确、分支不存在或工作树目标与本约定不符，先停止写入并说明，不猜测、不回退到默认分支。
